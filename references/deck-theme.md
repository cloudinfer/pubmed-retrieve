# 学术汇报 deck 设计规范 · 医学深蓝

本文件是 Phase 6 生成学术汇报 PPT 的**唯一美学依据**。
方法论参考 `op7418/guizang-ppt-skill` 的 Style B「瑞士国际主义」体系：
网格至上、单一锚点色、直角色块、1px 发丝线、极致字号对比、无阴影无渐变。
主题色改为**医学深蓝**，并针对生物医学文献汇报的场景收敛了版式数量与图表类型。

> 与归藏原技能的差异：归藏明确「不允许自定义 hex」，本技能则是**允许自定义但必须锁死**——
> 调色板即白名单，`deck_validate.py` 会拦截任何白名单外的颜色。

---

## 1. 何时使用

| 场景 | 适用 |
|------|------|
| 文献调研结果向课题组 / 领导 / 科室汇报 | ✅ 主场景 |
| 系统综述前期文献摸底、证据地图 | ✅ |
| 需要展示大量题录数据、分布统计 | ✅ |
| 需要细腻叙事、大量照片、品牌发布 | ❌（密度需求不符） |

**不适合**：把 CSV 原样贴成几十行表格的页面。文献表每页最多 4 条，超出请拆页或改走附录。

## 2. 调色板（白名单，禁止新增 hex）

医学深蓝体系 = **1 个锚点色 + 3 级中性墨 + 1 级浅底 + 1 个极少量警示色**。

| Token | Hex | 语义 | 典型用途 |
|-------|-----|------|----------|
| `--ink` | `#0A1B2E` | 主墨（近黑深蓝） | 大标题、正文、表格主文字 |
| `--ink-2` | `#4A5C72` | 次墨 | 副标题、说明、单位 |
| `--ink-3` | `#8593A3` | 弱墨 | 注脚、页码、时间戳 |
| `--anchor` | `#0A3D7C` | **医学深蓝**（锚点色） | 色块底、KPI 数字、强调条、图表主系列 |
| `--anchor-2` | `#2E6BA8` | 深蓝中间调 | 图表系列 2、次级色块 |
| `--anchor-3` | `#8FB3D9` | 深蓝浅调 | 图表系列 3、底纹块 |
| `--wash` | `#EEF3F9` | 冷灰蓝浅底 | 区块底、表头底、斑马行 |
| `--hairline` | `#CBD7E4` | 发丝线（1px） | 分隔线、网格线、表格框 |
| `--paper` | `#FFFFFF` | 纸底 | 页面底色 |
| `--alert` | `#B01E28` | 学术红（**警示专用**） | 仅用于负向指标、口径风险提示，全篇 ≤ 2 处 |

### 硬约束

1. **白色与调色板之外的 hex 一律不出现**（`#FFF` / `#000` / `rgba(...)` 灰阶均不豁免，需改用 token）。
   唯一例外是**运行时外壳色**（不属于页面内容，仅出现在翻页运行时里）：

   | 外壳色 | Hex | 用途 |
   |--------|-----|------|
   | `--chrome-bg` | `#DFE5EC` | 画布外的窗口底色 |
   | `--chrome-idle` | `#A9B6C6` | 未选中页码指示块 |

2. **`--alert` 全篇出现次数 ≤ 2**，且不得用于装饰。
3. 深色底页面（Cover / Closing）统一用 `--anchor` 作底、`--paper` 作字，
   禁止用 `--ink` 作底（太黑，丧失医学感）。

### 数据图表配色（沿用同一白名单）

```
主系列   --anchor    #0A3D7C
次系列   --anchor-2  #2E6BA8
第三系列 --anchor-3  #8FB3D9
弱化/对照 --hairline #CBD7E4
负向/风险 --alert    #B01E28   （仅在趋势下滑、口径风险时使用）
```

## 3. 字体

不引入任何 web font（单文件、离线可用）。

```css
--font-sans: "Inter", "Helvetica Neue", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-num:  "Inter", "Helvetica Neue", Arial, sans-serif;
```

| 用途 | 字体 | 字重 | 说明 |
|------|------|------|------|
| 中文标题/正文 | `--font-sans` | 400 / 500 | **全篇只用 400 与 500 两档** |
| 数字 / KPI / 年份 | `--font-num` | 400 / 500 | 加 `font-variant-numeric: tabular-nums` |
| 检索式 / PMID / DOI | `ui-monospace, Consolas, monospace` | 400 | 等宽，保证字符对齐 |

**禁止** 600 / 700 / 900 字重，禁止斜体（`font-style: italic`），禁止下划线（链接除外）。

## 4. 画布与网格

- 画布 **1600 × 900**（16:9），`transform: scale()` 自适应窗口，不改内部坐标。
- **16 列网格**，列间距 24px，两侧安全边距 **96px**。
- 纵向安全边距：顶 88px、底 84px（页脚区占底部 56px）。
- 内容区实际宽度 = 1600 − 96×2 = **1408px**；单列宽 = (1408 − 24×15) / 16 = **65.5px**。

常见栅格用法：

| 版式元素 | grid-column |
|----------|-------------|
| 全幅 | `1 / 17` |
| 左文 7 + 右图 9 | `1 / 8` 与 `8 / 17` |
| 左右等分 | `1 / 9` 与 `9 / 17` |
| 三栏 | `1 / 6`、`6 / 12`、`12 / 17` |
| 四栏 KPI | 每栏 4 列 |

### 硬约束

1. **直角**：`border-radius: 0`，全篇无一处圆角。
2. **无阴影**：`box-shadow: none`，无 `text-shadow`，无 `filter: blur()`。
3. **无渐变**：`linear-gradient` / `radial-gradient` 一律禁止。数据可视化需要层次时用**纯色块**或**透明度**（仅限 `opacity`，不引入新颜色）。
4. **发丝线一律 1px**，颜色只用 `--hairline`；强调分隔线可用 4px `--anchor` 色条。
5. 不允许 `position: fixed`。

## 5. 字号阶梯（极致对比）

| 层级 | 字号 | 字重 | 字距 | 用途 |
|------|------|------|------|------|
| `kpi-xl` | 160px | 500 | −0.04em | 单页唯一大数字（M05 / M09 主数字） |
| `kpi-l` | 96px | 500 | −0.03em | KPI Tower 次级数字 |
| `display` | 72px | 500 | −0.02em | Cover 主标题、Statement 大字 |
| `h1` | 56px | 500 | −0.01em | 页面主标题 |
| `h2` | 40px | 500 | 0 | 区块标题、Duo Compare 栏标题 |
| `h3` | 28px | 500 | 0 | 卡片标题、表格行标题 |
| `body` | 20px | 400 | 0 | 正文，行高 1.6 |
| `body-s` | 17px | 400 | 0 | 次要正文、表格内容 |
| `caption` | 15px | 400 | 0 | 注脚、来源、单位 |
| `eyebrow` | 13px | 500 | 0.14em | 页眉标签，**全大写西文 / 中文不适用大写** |

**下限硬约束：全篇最小字号 13px**，低于 13px 直接判 P0。
中文大标题（`display` / `h1`）在字数 > 12 字时**降一档**使用，避免挤压正文与图表区。

## 6. 中文排版细则

- 中英混排时，中西文之间**不手动加空格**，交由渲染器处理；数字与单位之间加半角空格（`24 篇`、`9 个`）。
- 标题**禁止居中**（瑞士风硬规则），一律左对齐贴网格线。
- 段落首行**不缩进**，用段间距（`margin-bottom: 0.8em`）区分。
- 正文单栏每行**不超过 34 个汉字**，超出需分栏。
- 禁则：行首不出现 `，。；：、）》"` 等标点（`line-break: strict`）。

---

## 7. 图表规范

本技能**不生成 AI 配图**，所有视觉元素来自 CSV 数据，用**内联 SVG** 绘制（无 CDN、无图表库）。

| 图表 | 用途 | 规范 |
|------|------|------|
| `bar-h` | 期刊分布 Top N | 条形高度 24px，条间距 16px，数值右对齐贴条尾，标签左对齐占 4 列 |
| `line` | 年份趋势 | 折线 2px，节点 6px 直角方块（**不用圆点**），基线 1px `--hairline`，无面积填充 |
| `matrix` | 主题 × 年份热力 | 方格纯色，透明度按占比分 4 档（0.25 / 0.5 / 0.75 / 1.0），不引入新色 |
| `tower` | KPI 四联 | 4 个等宽块，数字上、标签下，块间 1px 发丝线分隔 |

### 硬约束

1. 图表**无图例框**，系列名直接标注在图形旁（direct labeling）。
2. 图表**无 3D、无阴影、无渐变、无圆点**，坐标轴只保留基线，不画网格背景。
3. 每张图必须有 `caption` 级来源注脚（数据来源：PubMed，检索日期）。
4. **分桶统计可多重归类**，占比之和 > 100%，图注必须写明
   「同一文献可归属多个主题，占比之和大于 100%」。

## 8. 页帧（每页必须有）

```
[eyebrow]  M04 · 检索策略                                    页码 04
─────────────────────────────────────────────────────── 1px hairline
                     正文内容区
─────────────────────────────────────────────────────── 1px hairline
[footer]  PubMed 文献调研 · 检索式 …                      2026-10-02
```

- 页眉 `eyebrow`：左侧为「版式编号 · 页面主题」，右侧为两位页码。
- 页脚：左侧为检索主题摘要（≤ 40 字），右侧为检索日期。
- 页眉页脚均为 `caption` / `eyebrow` 级，颜色 `--ink-3`。
- Cover 与 Closing **不显示**页眉页脚。

**硬约束**：除 Cover / Closing 外，**每页必须同时存在 2 条发丝线、页码、页脚**，
缺任一项判 P1。页码从 Cover 起算为 `01`。

---

## 9. 节奏

- **hero / non-hero 交替**：深蓝满底页（Cover、Closing）之间至少间隔 4 页白底页。
- 数据页（M06–M08）不可连续超过 2 页，中间必须插入一页解读（M09 / M10 / M11）。
- 单页信息密度上限：**1 个主标题 + 1 个视觉主体 + ≤ 3 条说明**。塞不下就拆页。

## 10. 禁止清单（校验器会拦）

| 编号 | 禁止项 | 级别 |
|------|--------|------|
| F01 | 调色板外的 hex 颜色 | P0 |
| F02 | `border-radius` 非 0 | P0 |
| F03 | 任何 `box-shadow` / `text-shadow` | P0 |
| F04 | `linear-gradient` / `radial-gradient` | P0 |
| F05 | 字号 < 13px | P0 |
| F06 | `font-weight` 为 600 / 700 / 900 | P1 |
| F07 | 标题 `text-align: center` | P1 |
| F08 | 引入外部资源（`<img>` / `<link>` / `<script src>` / `@import`） | P0 |
| F09 | 非 Cover/Closing 页缺少页眉、页脚或页码 | P1 |
| F10 | `data-layout` 不在 M01–M20 之内 | P0 |
| F11 | 表格单页超过 4 行文献条目 | P1 |
| F12 | `--alert` 全篇出现超过 2 处 | P1 |
| F13 | `data-dark` 与版式不符（M01/M12 须深底，其余须白底） | P1 |
| F14 | 综述层残缺：出现 M13/M14/M18 中的任意页，却缺其余页 | P1 |
| F15 | M13 的 PICOS 为占位内容（未随 `review_evidence.json` 的 `meta.picos` 提供） | P1 |

> F14 / F15 针对的是「deck 与系统综述脱节」。综述层是成套的：只显示研究问题却不显示
> 筛选流程与结论，读者会以为问题已被回答；PICOS 退回占位则意味着该页没有任何主题专属的
> 人群描述——历史上它曾退回渲染器里硬编码的旧主题人群。两者配合 `--strict` 即成为交付阻断。
>
> 校验命令见 `scripts/deck_validate.py`，用法写入 `SKILL.md` Phase 6。
